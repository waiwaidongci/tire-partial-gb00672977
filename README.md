# 公交轮胎磨耗相关排查

澄湾公交集团北场机务班，服务 B12、K07、N03、S21 四条线路，10 月先导盘点覆盖 60 条轮胎。。机务员月底用 Excel 对齐轮胎履历、冷态胎压巡检、车载急制动与客流载荷台账，以粗相关挑选点检对象。台账员合并同一观测窗口的数据，车队技师复核线路差异，早班检修调度接收复核报告。

导入 beichang-tire-wear-2026-10.csv，每条轮胎一行。磨耗为期初胎纹深度减期末胎纹深度，轮胎编号在窗口内唯一。里程、胎压巡检、急制动及车组在线路上的平均载荷均取同期口径，胎龄以窗口起始日为准。 同一批记录的粗 Spearman、偏秩相关及差值，附全队和分线路诊断、复核动作与可分发状态，供机务班安排点检和补数。

- 把巡检占比直接与磨耗排序时，高里程和高胎龄的轮胎会挤到名单前面。
- 同一个全队粗相关数掩盖了线路之间的方向差异，技师难以定抽查范围。
- Excel 手工筛选时，低样本线路和重复编号容易混入待下发的名单。

## 六个业务模块

1. 北场磨耗总览
2. 轮胎窗口台账
3. 偏秩排查配置
4. 线路相关与诊断
5. 机务抽检复核
6. 检修交班报告

## 工作剧本

1. 08:10，北场机务班打开 2026-10-31 窗口总览，准备核对四条线路的 60 条轮胎。
2. 08:20，台账员导入 beichang-tire-wear-2026-10.csv，核对 B12、K07、N03 各 18 条，S21 有 6 条。
3. 08:35，技师以低胎压检测占比为待查指标，选里程＋胎龄，关联复核线设为 0.30。
4. 08:40，查看同一批轮胎全队粗相关 0.6955、偏秩相关 0.2531，记录全队控制后衰减。
5. 09:00，单列 K07 的偏秩相关 -0.7577，安排抽核巡检记录；S21 距 8 条判读门槛还差 2 条，挂起线路结论。
6. 09:20，试跑里程＋线路载荷，记录全队偏秩相关 0.3480，保留两种口径供技师复核。
7. 10:00，经复核后导出默认口径的结果表，交北场早班检修调度在 11:00 交班会分发。

## 算法与复核

并列值取平均秩。粗值为待查指标秩和磨耗秩的 Pearson 相关；偏秩是两列秩分别对所选控制项的秩做线性回归后，两个残差向量的 Pearson 相关。全队与各线路独立排秩。结果用于点检排序，可能受未纳入的胎批、轮位和共享车辆工况影响。

混窗、轮胎编号重复、无效数值、全队少于 12 条或少于 2 条线路时退回导入补正。线路少于 8 条时保留诊断，偏秩留空。控制项无秩变异或共线、残差无变异及严重数值诊断时须复核，全队不满足诊断要求即暂停分发。 复核问题为「控制里程及所选工况后，哪些线路应安排同条件复测，哪些先核对控制项或补齐轮胎记录？」。每次分析绑定数据版本和参数，原始数据按规范化内容的 SHA-256 去重。日程针对已复核的固定结果版本，每日模式按初次投递时间每 24 小时重复。停机期间错过多次时只补一份到站内收件箱，下一次回到原时间点。

| 字段 | 含义 | 类型 |
|---|---|---|
| `tire_id` | 轮胎编号 | str |
| `route` | 线路 | str |
| `window_end` | 窗口截止日（YYYY-MM-DD） | str |
| `mileage_km` | 窗口里程（公里） | float |
| `tire_age_days` | 期初胎龄（天） | int |
| `route_load_pct` | 车组在线路上的平均载荷率（%） | float |
| `low_pressure_pct` | 低胎压检测占比（%） | float |
| `hard_brakes_per_1000km` | 急制动频次（次/千公里） | float |
| `tread_loss_mm` | 胎纹磨耗（毫米） | float |

## 启动

```sh
[ -f .env ] || cp .env.example .env
docker compose up -d --build --wait
docker compose exec -T backend python -m scripts.seed_demo
```

- Web 界面 `http://127.0.0.1:18291`
- API 文档 `http://127.0.0.1:19291/docs`
- 数据库端口 `17791`

| 账号 | 演示密码 | 工作权限 |
|---|---|---|
| analyst | analyst-demo-24 | 导入 CSV、运行分析、导出工作稿 |
| reviewer | reviewer-demo-24 | 复核、设置和停止投递、导出 |
| viewer | viewer-demo-24 | 浏览结果、导出已批准的报告、查收投递 |

原生 HTML/CSS/JavaScript 前端与 Nginx、FastAPI、Python worker、MySQL 8.0 和 Redis 组成五服务 Compose。`backend/src/services/domain.py` 存放业务算法，`domain.json` 定义字段与验收口径，`frontend/src/pages` 为业务页面。更新任一侧源文件后，用 `docker compose up -d --build` 重建对应镜像。`backend/src/constants/enums.py` 和 `frontend/src/constants/enums.js` 定义角色及运行状态。`.env` 支持前端、API、数据库端口、演示 seed 开关和 JWT 密钥。首次部署到非演示环境时更换演示身份及 JWT/数据库凭据。

`docker compose down` 停止服务并保留数据卷。现场数据和演示结果可以在各自版本中并存。
